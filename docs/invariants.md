# Invariants and stage contracts

Code comments and docstrings are not used in this repository. This page records the invariants that the code alone does not explain, and the module or function that owns each one. Each entry gives the owner, what goes in, what comes out, and the failure boundary, meaning what fails and what is guaranteed not to be published. Numerical references live in the tests named here. A change that breaks an invariant must update the tests and this page in the same change.

Open implementation work is tracked in [TODO.md](../TODO.md). Current operation receipts and the measured native execution restrictions are in [GA measurements](ga-measurements.md). Optional [teacher–student operation](teacher-student-cycle.md) and [specialist routing](specialist-portfolio.md) are separate designs.

## Corpus construction and training

`bench.procedures pack` and `bench.support pack` explicitly construct and publish corpora. `bench/zt411_gpu.sh` consumes an existing publication and stages its verified labels and evidence assignment through `bench.evidence`; it never invokes either builder or supplies review inputs. A missing manifest stops the runner before creating work. Restarting training does not regenerate scenarios, recompute published labels or republish review history. Builder commands are offline; they remain separate intentional operations. `tests/test_primary_experiment.py` exercises missing input and repeated failed staging for both supported domains without allowing any builder invocation.

A run binds one publication: `bench.evidence.bind_corpus` stages under `WORK/stages/<digest[:16]>` and publishes `WORK/stage.json` carrying the full `benchmark.json` SHA-256 before any work. A restart compares the observed manifest digest against that retained binding before staging; a different publication is refused with both digests and leaves the binding, stage and audit ledger untouched. `bench.snapshots --corpus DIGEST` verifies the same digest before scoring, reads the pack once, records the digest in the experiment fingerprint and declares the primary comparison (`workflow|structured`, targets, margin, language population). Missing or corrupt payloads fail with their paths; reading never invokes generation, review writers, publication or pruning. Stages, exports, profiles, candidates and reports are written under the run's work/results directories.

## Numerical objective

| Invariant | Owner | Inputs → outputs | Failure boundary |
| --- | --- | --- | --- |
| **Full-vocabulary normalization.** Loss v2 is `softplus(logsumexp(z[not G]) - logsumexp(z[G]))` over the whole vocabulary at the answer position. `G` is the union of the gold group's tokens. The gold complement is computed sparsely as `peak + log(sum exp(min(z - peak, 0)) - sum_G exp(min(z_g - peak, 0)))`, where `peak` is the largest non-gold logit found by a top-(\|G\|+1) search; no vocabulary-sized mask or complement copy exists. Probabilities and the reported answer mass `exp(logsumexp(legal) - logsumexp(all))` use the same full-vocabulary denominator. Normalizing only over the answer slots is a separate diagnostic (`SlotLoss.conditional`) and is never the objective. | `semantic_trainer.objective.slot_statistics`, `slot_loss`; machine descriptor `jobs.LOSS`; native counterpart `semantic_switch.backend.reduce_row` (fp64) | float logits `[rows, vocab]` and `PackedSlots` → `SlotStatistics` (per-group logsumexp, chosen, complement, union, total) and `SlotLoss` (nll, conditional, mass) | `update`/`evaluate` raise `NumericalFailure` on any nonfinite logit, loss or gradient norm. No candidate is published. Independent float64 references: `tests/test_lora.py` (loss/gradient, uneven groups, native reducer agreement). |
| **Padded slot coordinates.** `PackedSlots` holds only `index`/`valid`/`present`/`gold`: answer groups padded to a common width, the padding masked to `-inf` before any logsumexp, and the gold group per row. There are no `legal`/`golden` coordinate lists and no `objective.membership` scatter. A token that appears in two groups is rejected earlier by `jobs.answer_groups`. | `objective.packed`; group validation `jobs.answer_groups` | `Answers(groups, label)` per presentation → `PackedSlots` on the logits device | Overlapping, empty or out-of-vocabulary groups fail at `answer_groups` during preparation, before any model is loaded. |
| **Gathered head projection.** `objective.bind(model)` resolves the PEFT text trunk, vocabulary head, Gemma softcap and host table once. `answer_logits(binding, ...)` keeps right padding and masks, gathers the last real hidden state `[row, length-1]` into `[B, H]` and projects only those rows to `[B, V]`. Fit, profile and monitoring all use this operation. | `objective.bind`, `objective.answer_logits` | binding + padded batch → `[B, V]` logits | Gradient and logit equivalence against full-forward references for unequal lengths, nonzero adapters and softcapping (`tests/test_lora.py`). |
| **Stage weighting.** Each observation contributes total weight `objective` (its task weight). Inside an observation, the weight is split equally across its presentation stages and then equally across the variants of each stage (`presentation_weights`). A batch averages over observations, not presentations. Monitoring NLL uses the same weights. Microbatch chunking and order do not change the summed gradient. | `jobs.presentation_weights`, `jobs.objective_weights`; `objective.accumulate`, `objective.evaluate`; `monitor.Monitor.point` | prepared `Inputs` (built once per run by `objective.prepared`) + batch → summed weighted loss/gradient, or per-row weighted NLL | `test_weighted_gradients_are_invariant_to_chunking_and_within_batch_order`, `test_prepared_inputs_are_built_once_and_reproduce_the_stage_weighted_reference`. |

`objective` owns every numerical and input operation: input preparation, slot packing, collation, host-table embedding, forward, reduction, update, evaluation and schedule. Monitoring is windowed (`objective.windows`/`readout`): a bounded window is partitioned by the independent evaluation batch cap and padded-token limit; each forward transfers compact answer statistics to CPU. The default evaluation cap is one. Disabled fit probes make no forwards. `lora.train` and `lora.profile` are wrappers over `trained_run`/`profiled`, which take resolved records. Both call the same `objective.update`, and both evaluate through `monitor.Monitor.point`. Profile measurements therefore describe the production computation. Runtime-adapter selection proves its zero adapter by `deploy.verify_runtime_zero` (zero `lora_B` factors plus the pipeline base digest) without merging.

## Monitoring and stopping

| Invariant | Owner | Inputs → outputs | Failure boundary |
| --- | --- | --- | --- |
| **Monitor stop precedence.** The fit loop stops at the first of: token budget (`token_budget`), monitor budget (`monitor_budget`), deadline (`time_budget`), plateau (`loss_plateau`) or epoch cap (`epoch_cap`). At the same final boundary, an expired deadline overrides a plateau or the epoch cap (`crossed: final_boundary`). A point whose rows all completed after expiry is kept with `completed_after_deadline`, may take its one checkpoint, and then stops on `time_budget`. A point interrupted mid-row is recorded as `interrupted_evaluation` with its reserved and charged tokens and is never ranked. Convergence is claimed only for a plateau whose best point is not the last evaluated point. | `monitor.Deadline`, `monitor.Monitor.point`, `monitor.stopped`, `monitor.feasibility`; loop in `lora.fit` | elapsed clock, work counters, points → stop record (reason, deadline, unevaluated work, best point, work, inputs) | `Exhausted` ends the loop and is converted into a stop record. With no fully evaluated nonzero point, `stopped` raises and the run publishes `failed` with no candidates. `Infeasible` (projection beyond budget after the first K updates) fails before further fitting. |
| **Retention.** `candidates/` holds the zero adapter and at most `RETAINED` ranked points. Each point is staged, saved and renamed before evicted points are removed, and the ranking rule is published with them. | `monitor.retain`, `monitor.checkpoint` | model + point + previous retained → new retained list | A crash mid-save leaves only a `.staging` directory, so earlier retained candidates stay intact. |

## Evidence, families and corrections

| Invariant | Owner | Inputs → outputs | Failure boundary |
| --- | --- | --- | --- |
| **Family closure.** A family is the connected component (union–find) of every raw group, pair and shared `key`/`observation`/`rendered`/`situation` seed. Roles, quotas, independence and statistical grouping are assigned per component, never per raw group. Inherited warm-start memberships join the same closure. | `semantic_switch.families.FamilyIndex`; `jobs.cohort`, `jobs.separated`; core `examples`/`Labels.component` | seeds per observation → component id and member seeds | A component that spans fit and evaluation roles, or source components that cross roles, fails preparation (`separated`). Lineage that cannot be resolved to components is `unknown`, never `declared_disjoint`. |
| **Frozen correction membership.** Exact corrections are resolved once, during preparation, from authored examples plus the declared sidecar. The resulting override population (active `exact_override` only) is frozen with the task. Selection and freeze use that population and never ambient `.examples.jsonl`. Provenance declares overrides as the `override` use, merged into an existing row when the observation is already declared. | `jobs.override_population`; `semantic_switch.tools.deployment.freeze_specialization`; `artifacts.USES` | frozen task overrides + cohort rows → `corrections` in the resolved job; provenance rows tagged `override` | A correction contradicting an exported observation fails preparation. If the declared `override` provenance differs from the active override population, freeze fails and nothing is published. Old deployments with undeclared active overrides are reported as `undeclared_overrides`, not as disjoint. |
| **Label provenance: derivation, verification and permitted use.** Each target's label history records three independent dimensions. *Derivation* says how the answer was established: `computed` by a deterministic procedure (producer = procedure id, `revision` required), `judged` by a judge/model (producer = observed route, `revision` = producer identity digest) or `authored` by someone writing it directly (`actor` required: `human`, `agent` with model and session, or `unknown` for undocumented historical authorship); `unknown` remains for imported labels. *Verifications* are appended records (`verifier`, `actor` human or agent, `method` procedure-recompute/source-check/review, `criterion` revision, content digest, outcome) written by `ss label` and the pack review; authorship by a human is never verification. `assess(history, data, path, value, criteria)` derives one per-target `Assessment` before any aggregation and requires the effective `Criteria`: label verifications must name the target's current meaning revision (or a declared review binding), evidence verifications a declared review binding; a missing binding yields `unassessed`, never wildcard acceptance. A confirmation counts only on the current (uncorrected) segment, bound to the addressed content; replaced, rebound or out-of-criterion records are stale, a current skip alone is `disputed`, and a current confirm plus a contrary record is `conflicting`. Full-frame source fidelity is reported separately (`fidelity`). `Task.assess(record, review)` and the deployment owner derive the identical criteria (`examples.assessments`) from the task plus the evidence manifest's declared review bindings; stored comparison rows and round coverage freeze that binding, and a stored reference without it is unassessed. `label_provenance(plan, records, review)` aggregates with explicit counts. *Permitted use* is the `TrainingUse` declaration, carried only by judged labels. Only an authored decision replaces a value, and the replaced sources stay in the history. Family/role exposure accounting ignores all three. | `semantic_switch.evidence.LabelSource`/`Verification`/`Actor`, `assess`/`Assessment`/`Criteria`/`assessments`, `label_provenance`; `training.Task.assess`; `permissions.admit`; `training.Task.admit`; `tools.label`; `Switch.correct`; `bench.evidence.sources_for` | label history → envelope `label_sources` (schema 3), export rows (`label_derivation`), report `label_provenance`; `permissions.admit(addressed histories)` → admitted count or `ConfigError` | `admit` fails preparation when any source in the history, replaced or verified or not, comes from a restricted producer (Jev) or is a judged label without an allowed declaration for its exact route; computed and authored labels need no provider declaration. A verification whose content digest no longer matches the input/value fails `label_record`. `test_label_import`, `test_bench_provenance`, `test_specialize::test_prepare_rechecks_judged_training_provenance_without_semantic_learn`, `test_rounds::test_human_authorship_is_not_verification_and_any_confirmed_verifier_counts`. |
| **Correction-history accumulation.** Repeated envelopes for one input accumulate as a set of immutable claims (value plus complete ordered source history) per target address, beside unioned groups/pairs/tags/selections; accumulation is associative, commutative and idempotent and chooses no winner. `resolve_claims` settles once at materialization over indexed explicit edges: a claim is superseded only when its chained trajectory identity is a prefix of another claim's (the successor that `examples.successor` builds from its addressed predecessors) or an authored `resolves` decision names it and carries its sources; equal answers, timestamps and file order establish nothing. Equal-value corroboration appends without moving the correction boundary, a changed value records `replaces` (an explicit null is distinct from a missing `replaces`), and a decision over unresolved alternatives names every predecessor. Independent equal-valued chains merge only when one ordered history keeps every step value; otherwise, and for competing terminal values, the target stays unresolved with every alternative retained. Source identity excludes appended verifications, which merge by identity. `Switch.correct`, `Snapshot.with_example`, `collect` and `ss label --stale` apply this same reduction; stale relabelling keeps the old history under its old criterion and preserves sampling metadata. | `semantic_switch.evidence.Claim`/`resolve_claims`/`successor`/`Accumulator`/`settle`/`resolution`; `training.Task.accumulator`/`merge`/`resolve`; `semantic_learn.review.Population`, `semantic_learn.rounds.eligible` | envelopes → `Accumulator.settle(strict)` → envelope plus unresolved claims | strict materialization (fitting, rounds) raises on unresolved targets; review emits a partial envelope plus `claims.jsonl`; overflow of the claim budget fails before dropping provenance. `test_accumulation`, `test_rounds::test_round_preparation_and_review_settle_correction_histories_exactly_like_core`. |

Unknown provenance is `unknown`, never `declared_disjoint`. | `artifacts.family_overlap`; adapters `tools.lock.overlap_of`, `tools.deployment.assess_lineage` | membership rows + scope + `(key, family, projection)` items → `LineageAssessment` | Overlap withholds intervals and adoption claims; it never drops rows. `test_adaptation_contracts`, `test_primary_experiment`. |
| **Counting.** `metrics.Counts` is the one streaming reducer over canonical `(correct, accepted, outcome)` rows; `correctness`, `success` and `Progress` are its projections and `rates` its one rates projection. | **Fitted-record proof.** `candidates.json.fitted_job_id` must equal the canonical digest of the run's original `resolved-job.json`. Job, fit and monitor identities must agree across run, candidate list and fitted record. No step rehashes edited metadata. | `jobs.ready_run`; `select` candidate validation; `adapter.verified` | run directory → validated `(state, listed, fitted)` | Missing digest is missing proof. ## Lifecycle and publication

| Invariant | Owner | Inputs → outputs | Failure boundary |
| --- | --- | --- | --- |
| **Borrowed/owned resource lifecycle.** A `Runtime` owns the judges it constructs from a specification string (`_constructed`), plus every model it loads. A judge, model or transport passed in by the caller is borrowed and is not closed, unless `own_judges=True` explicitly transfers ownership. Each resource is closed at most once (deduplicated by resident identity). A `ModelJob` passed in is borrowed; otherwise the runtime owns its job stack. `Wire` lazily creates and owns its pooled HTTP client and releases it on `close`. Hosted close is idempotent and concurrent-safe; `HostedJudge.aclose()` uses the same close owner off the caller's event loop; an owned transport's `close` is optional (sync or async) and invoked once; a borrowed transport is never closed. Hosted timing phases are disjoint: `seconds = queue + service + retry`. A selection `ScoreLedger` delegates to the trial scorer and releases only its own stored blocks; the integration handle owns the scorer. | `semantic_switch.api.Runtime.__init__`/`close`/`_install`; `hosted.Wire.close`; `training.Selection` | supplied bindings → close set | `close` inside an active operation raises. Cleanup errors are raised after every owned resource has been attempted (`ExceptionGroup` when there are several). |
| **Capture log.** semantic-learn capture is an append-only bounded log (schema 3: header line plus records) written through `files.append(path, files.jsonl(records))`, which takes complete encoded JSONL bytes. Pending encoded bytes flush at 64 KiB or close with one fsync per flush; reopen recovers only a torn final record. Disclosure distinguishes persisted, buffered and dropped records (`records`, `bytes`, `encoding`, `storage`). The redactor is invoked once per decision; repeatability is a redactor conformance test. | `semantic_learn.capture`; `files.append`/`files.jsonl` | decisions → log records | Storage failure preserves the decision and is disclosed; a record over the file budget is dropped and counted. |
| **Deployment comparison and promotion.** `ss compare` scores each arm over the check inputs in one bounded operation (`Switch.score(inputs, demand=[(labelled targets, True), ...])`; each demanded decision carries per-input admission-to-completion `elapsed_ms` and the operation receipt, as `Switch.run` does), journals rows per input under stable keys and publishes `comparison.json` plus `decision.json` (schema-2 promotion decision bound to the comparison id and both entry ids). `ss promote` moves a pointer to a decision's candidate only for a supported verdict and only while the pointer serves the decision's baseline; `ss rollback` names the incumbent it rolls back. Both are one compare-and-update under the pointer transaction lock. | `tools.deployment.compare_deployments`/`promotion_decision`/`promote`/`point`/`rollback` (also on `semantic_switch.training` with `DECISION_SCHEMA`); CLI `ss compare`/`promote`/`rollback` | locks + labels + evidence → report, decision; decision + pointer → new pointer | A stale incumbent, tampered decision or unsupported verdict changes nothing. Root `tests/test_deployment_promotion.py`. |
| **Doctor.** `ss doctor` reuses a complete cached native conformance result for the binding's cache key and reports `passed`/`failed`; a binding without a native self-test (hosted) is `unsupported` with no probe request. | `tools.doctor` | runtime role → report | Only failed checks exit nonzero. |
| **Publication commit.** An artifact exists only once its commit file is atomically renamed into place. Payloads are staged, fsynced and renamed first, then the manifest (`files.publish`). Directories are published by one same-filesystem rename of a fully fsynced staging directory (`files.publish_directory`). A pipeline stage is complete only when its completion unit is committed to the leased pipeline Journal, and its outputs re-verify on reuse. A `current` pointer changes atomically between verified locks. | `semantic_switch.files.publish`/`publish_directory`/`write_new`; `semantic_trainer.pipeline` (`execute`, `completed`); `tools.deployment.point` | staged bytes → committed manifest/directory/Journal unit | An interruption before the rename publishes nothing. A failed or cancelled stage commits a failure record and is never ready. Committed output that no longer verifies fails at that stage. |

`Switch.score(inputs, facts=None, *, sources, decide, demand, snap, reuse) -> list[Row]` is the training/tools integration operation: per input a `Row` with typed `Target`s (path, criterion, binding, source, distribution/mass, eligibility, pending/missing/error, status/acceptance/selection, observed models, request receipts, public `FactResult`) and, when demanded, the `SwitchResult` decision. ## Owned data, identities and measured execution

| Contract | Owner and boundary |
| --- | --- |
| Immutable input JSON | `context.json_value` validates and owns nested mappings and JSON arrays once. `OwnedJSON`/`JSONArray` reuse that ownership during render and projection. `Frame.values`, `Claim.value`, and `LabelSource.replaces` expose read-only descendants. Frame and Claim descriptors cannot be reassigned. Arbitrary mapping proxies are validated and copied. `record()` and mutable redactor callback inputs are explicit mutable boundaries. |
| Frozen result records | `results.freeze` returns already owned mappings unchanged; unknown mappings are recursively frozen into `OwnedMapping`. `files._json` uses the strict mapping encoder directly. YAML and public mutable records use `thaw`. |
| Lazy switch receipts | `results.Cost` retains typed `Request` references. Its request list is encoded once on access; `SwitchResult.as_dict(verbose=True)` creates the ordinary public JSON record. `deployment.compared_row` reads typed attempts and usage. Unobserved decisions do not call `Request.as_dict`. |
| Capture admission | `Capture._admitted` owns redaction, snapshot selection, inference and storage/drop accounting. Closing stops admission and drains wrappers before publication and resource release. Concurrent closers share completion; closing from an admitted wrapper rejects. Sampling affects retention only. A captured Task and its inference use the same pinned Snapshot. |
| Capture recovery | `Log._scan` accepts a complete matching header without newline and normalizes it under the writer lease. A mismatched valid header is untouched and rejected. Invalid final fragments are truncated; valid final records receive their newline. Disclosure counts persisted bytes after repair. |
| Encoded acquisition quota | `Accumulator` charges UTF-8 input keys, cached Claim records, and shared-encoder metadata payloads before mutation. Training recovery uses atomic checkpoint directories and one latest/previous pointer. State contains trainable parameters, optimizer/scheduler state, RNG and the next epoch/batch cursor; frozen weights and corpus payloads are referenced, never copied. Only complete evaluated points enter ranking. Finalization commits candidate/metric records before ready state and can be replayed without inference. A retry restores consumed monotonic time; time between invocations does not consume the allowance, and work after the last durable record may be unmeasured after a hard interruption.

Probability diagnostics, policy acceptance and reference agreement have distinct populations. Development curves never certify held-out accepted precision. Model-select checkpoint exposure cannot be removed by splitting the same rows afterward. Unknown facts can block relevant rules; confidently wrong facts may produce wrong decisions. Native determinism is scoped to the recorded build, model and execution shape.

### Specialization execution and recovery

`semantic_trainer.objective` owns preparation, batching, forward projection, reduction, update and deterministic epoch iteration. `Monitor` owns evaluation, stored-block reuse, counters and ranking. `lora` executes fit/profile through those operations; `pipeline` chooses and journals operations. `recovery` publishes standard adapter and optimizer state; it contains no second training loop.

The default specialization skips profiling and finalizes cadence to one fit epoch, retaining zero/final boundaries. Explicit profiles are checked against their actual configuration and workload. Their complete-operation timings and bounded sample are durable; failed partial profiles are not complete artifacts. Estimated duration is informational. Optional token ceilings are enforced only when supplied; sequence, padded-token and count bounds remain hard limits. A retry restores consumed monotonic time and excludes the gap between invocations.

The desktop recipe publishes a local model-select baseline before fitting. Majority choices come only from fit-role situations and use declared check class order for ties. They are primitive diagnostics, never invented workflow actions. Comparison defaults to local base/student; hosted reference arms require explicit selection. A declaration is not a provider spending ceiling. Machine battery/sleep policy is outside the library, CLI and runner.

`tools.specialize.invoke` owns an isolated trainer process group. Cancellation terminates the group, waits its grace interval, escalates and reaps its direct child. Existing memory-scope/guard cancellation reaches this owner. Phase timing synchronizes at the end only after a successful body. Error logging is CPU-only after device loss and must not mask the first error.

Recovery checkpoints are immutable staged directories published by same-filesystem rename and committed by a latest/previous pointer. They contain adapter weights/configuration, optimizer/scheduler state, used RNG states, epoch/next-batch cursor, work counters, plateau/ranking state and pending point identity. Frozen weights and corpus bytes are not copied. The default five-minute interval is operational; `train(..., checkpoint_seconds=...)`/`lora --checkpoint-seconds` change it without changing fit identity. Retention hard-links matching committed adapter files. Old recovery/candidate generations are pruned only after pointer publication, preserving candidates needed by the previous checkpoint.

Retry of the same attempt restores the original seeded epoch permutation, partial last batch, scheduler horizon and optimizer step. A new attempt starts from its declared initializer. Monitoring journals compact CPU blocks under checkpoint, role, row ordering and original batch plan; committed blocks are reused without inference or reshaping remaining batches. Only fully evaluated points enter ranking. Finalization durably records candidate descriptors and metrics before publishing ready state; replay of interrupted publication does not load a model. Unevaluated saved weights are never serving evidence.

Permutation diagnostics use the same reduced outputs as canonical monitoring, align slot maps to semantic classes including escape/unstated and retain no device tensors. Stage/variant support mismatches are unassessed. These diagnostics add no forwards and change neither loss nor ranking. Probability diagnostics and the existing lock development curves do not certify accepted precision or undo checkpoint-selection exposure.

Native candidate selection journals compact public observations and exported-token diagnostics under the fitted run, bound to the job, model/execution and row population. Publication retry reuses these rows through the same evaluator. Serving receipts contain candidate aggregates and a digest-bound `selection.rows.jsonl` payload; repeated verbose result/presentation trees are never embedded per observation. The deployment and initializer publisher share this row writer. A publication failure preserves the fitted model and committed selection evidence.

Membership transport stores each distinct `{family_seeds, sources}` descriptor once in the receipt's family table. Observation rows retain their own IDs, projections, targets, label-source digests and uses and reference the descriptor by content digest. `artifacts.membership_record` owns encoding; `membership_rows` owns expansion for receipts and lock predictor records. Receipt loading validates expanded membership once, then shares immutable descriptor values across the canonical provenance rows. Normalization never merges observations, drops lineage seeds or changes adaptation/selection exposure. `Receipt.data` remains the digest-verified serialized representation; `Receipt.provenance.rows` supplies canonical membership to consumers.
