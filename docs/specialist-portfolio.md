# Specialist portfolio design

Optional design exploration. This is not GA implementation work and adds no requirement to ordinary inference or the single-student teacher-monitoring cycle.

Implement only after these inputs exist:

- Current native, export and fitting baselines from [M1](ga-measurements.md).
- Current passing reference/layout controls for the proposed shared runtime-adapter execution scope from [native controls](ga-measurements.md). A different explicitly supported representation needs its own measured quality/resource evidence. Historical failures do not establish that every adapter is broken, but cannot support a claim of shared-path equivalence.
- Monitoring evidence that the incumbent student/generalist policy leaves a recurring, material gap. A proposal must identify that population and its expected incremental benefit before extending the core loop.

Serving remains one Executor. Catalogue, router and specialist publication use the existing deployment owner. No new agent framework, model registry service or background scheduler.

## 1. Frozen catalogue and compatible task scope

- **Defect:** bindings are static in Executor; scoped specialization receipts cannot load/compare as complete applications. The routing fixture classifies customer queues, not model suitability.
- **Change:** core deployment extends the frozen application lock with one routing descriptor: generalist binding, ordinary frozen router entry, specialist entries keyed by immutable receipt ID, addressed task/criterion/composition/input requirements, fitted acceptance reference and execution/resource descriptors. Catalogue is this descriptor's decoded view, not another registry/database. Compile target→eligible-entry ordinals once; preserve overlapping scopes. A discovery label cannot authorize a new criterion or widen a specialist's measured scope.
- **Change:** snapshots own the compiled catalogue, route presentations and bindings; Runtime.load recognizes the complete routed application through the existing decoder. Install scoped receipts only inside declared compatible targets. Parent exact rules, lexical heads and composition remain authoritative; differing tokenizers/framing prepare requests from the same owned frame. Shared primitive dependencies have one route contract and one scored state; incompatible parent demands refuse at compilation. Adding/removing entries changes portfolio/router execution identity, preserving unchanged task label meaning. Existing SDK load/run/results serve the application; routing details stay in opt-in receipts, not extra public facts or a new Router/Agent API.
- **Test:** empty catalogue reproduces generalist behavior; wrong target/criterion/reads/base or altered receipt cannot become eligible. Multi-target specialist scopes overlap without duplicated task definitions. Catalogue decoding and prompt preparation occur once per snapshot; no per-row YAML/Pydantic application compilation.

## 2. Route and defer in the existing operation

- **Defect:** a wrapper that calls router→specialist→generalist independently duplicates eligibility, stages, cancellation, receipts and policy handling; availability of a generalist cannot catch confidently wrong accepted answers.
- **Change:** extend Call/FactState with route result, selected binding and bounded attempt receipts. Route only unresolved judge work after canonical exact/head precedence. Compile eligible binding IDs into an ordinary routing Pick; router requests/completions use Operation's existing queue. Zero specialist eligibility selects the generalist exactly. Uncertain/failed/invalid router output selects the generalist; exclude any retired/incompatible ID. No nested per-row Runtime.ask loop or second acceptance engine.
- **Change:** prepare/score the selected binding with its frozen acceptance policy, preserving complete Select/focus stages. Model uncertainty or a declared recoverable candidate failure may invoke the generalist once; missing required caller fields do not trigger useless escalation. Attempt stage states are isolated: fallback restarts from original input/eligibility, never the specialist's narrowed candidates or partial Select answers. First implementation attempts at most one specialist plus the generalist per primitive target; only terminal accepted/withheld state enters composition, while receipts retain prior attempts. One Call deadline supplies remaining budget to every route/score unit; do not claim hard preemption of in-flight native decode. Cancellation/MemoryError propagate; generalist can withhold/fail too.
- **Test:** exact/head bypass, uncertain router, stale ID, confident wrong specialist, fallback failure, multi-stage Select, ordered completion and cancellation. Accepted specialist calls do not secretly run the generalist; independent sampled shadowing detects their errors. Receipts include route and every attempted binding's work/cost, not just the final answer.

## 3. Demand detection and one shared observation population

- **Defect:** training a new model for every novel-looking cluster duplicates data and grows a model zoo; text similarity and new family IDs do not establish a reusable capability or profitable traffic.
- **Change:** semantic-learn indexes [bounded cycle](teacher-student-cycle.md#91-bounded-cycle) observations by target/criterion, existing failure-category labels and declared scope features; proposal membership stores observation ordinals, family references, event multiplicity and selection provenance. Reuse input/token/source tables and cached projections. A row may support several proposals without another payload copy; use one bounded offset/ordinal index, not per-specialist Journals or a vector database. Offline semantic triage proposes groups; runtime routing uses only compiled scopes.
- **Change:** each bounded proposal chooses create, update an existing specialist, consolidate or retain current portfolio. Rank by expected *incremental* benefit over current routed traffic: `N_horizon × (C_current - C_proposed) - C_teacher_data - C_fit - C_evaluate - C_incremental_residency`. C includes routing, rejected attempts, fallback, shadowing and cache/load work. Bind horizon, volume uncertainty, measurements/estimates, independent families and compute limits. Missing measurements may fund one feasibility trial from a declared exploration budget; estimates never authorize deployment. Quality/coverage constraints are measured separately, not a scalar error-price invented by the judge.
- **Test:** near-duplicate/overlapping proposals share storage and cannot claim the same traffic saving twice. Low volume, high fallback, expensive routing and cold-adapter churn can make benefit nonpositive. Existing specialist reuse beats unnecessary creation; reported estimates remain distinct from measured serving savings.

## 4. Joint specialist/router training with separate evidence roles

- **Defect:** a specialist improvement changes router labels; training the router only on its chosen model creates selection bias and leaves alternative performance unknown.
- **Change:** cycle sends eligible evidence through collect/review/round and existing trainer.pipeline. Mix targeted failures with representative permitted older cases in one weighted population. Freeze specialist candidates, then score bounded `(observation, candidate)` pairs on development families through Switch.score. Router labels select the cheapest eligible binding whose valid settled prediction matches the declared reference, including fallback/resource costs; confidence alone is insufficient. Unknown pairs stay unknown; no acceptable known action defers to generalist without inventing a correctness label. Judged references teach fidelity, not verified truth. Fit the router through the same semantic task/specialization path; new options invalidate its label space/calibration.
- **Change:** use existing fit/model_select/acceptance_fit/check assignments with family and ancestral exposure closure for both specialist and router optimization. Computed router labels name their procedure revision and retain reference/teacher permissions and ancestry; they cannot upgrade judged truth to verified application references. Router features exist before selection: input projection, task/catalogue descriptors; final answer, future feedback and teacher verdict are excluded. Log action/inclusion probabilities; bounded randomized shadow comparisons supply missing alternatives offline. No second loss, token-level MoE or all-models-per-request evaluation.
- **Test:** changing specialist performance changes affected router labels/IDs; unseen actions are not filled with assumed failures. A strong specialist routed incorrectly lowers full-policy quality. Teacher-blind scoring, feature availability, shared-family exclusion and compute counts hold across resume and candidate replacement.

## 5. Evaluate and calibrate the complete routed policy

- **Defect:** existing comparison rejects scoped-only arms; per-specialist quality or teacher agreement does not prove that a router, fitted thresholds and fallback produce an acceptable application.
- **Change:** extend Entry/compare_deployments to decode complete routed applications, retaining one comparison, exposure ledger, row producer and decision reducer. Freeze task, catalogue, router, acceptance and fallback identities before check consultation. Lineage closes over every participating router/specialist/initializer/threshold-fit population, including inherited evidence; build its family index once, not per input. Aggregate complete/target quality and coverage, failures/forbidden outcomes, route/fallback counts, per-scope results and total latency/cost/memory. Compare whole portfolios on identical inputs; specialist-only/router-oracle diagnostics remain development attribution.
- **Change:** fit acceptance/deferral using all held-out calibration outcomes, including incorrect confident answers, with explicit risk denominator/coverage and per-task execution scope. Preserve sparse/degenerate/inconclusive outcomes. A quantile of scores on correct examples alone cannot bound accepted-error risk; do not copy that purported guarantee. Conformal/risk-control additions require the actual loss, sampling assumptions and finite-sample correction, plus [production monitoring](teacher-student-cycle.md#94-monitoring); no per-input guarantee or automatic validity under distribution shift. Initial implementation retains the existing measured policy fitting/evaluation owner.
- **Test:** all wrong examples have lower uncertainty than correct ones: calibration cannot certify safety from correct-only quantiles. Router-only or inherited specialist training overlap with check families withholds independence. Compare wrong routing, high-mass wrong answers, increased withholding, fallback costs and scoped regressions. Recompute stored reports without inference; changing router/catalogue/thresholds requires a new frozen comparison.

## 6. Shared-base residency and bounded routing transport

- **Defect:** many adapters fragment batches, cause load/eviction churn and retain role views; S-LoRA's heterogeneous CUDA kernels do not exist in this serial llama.cpp scorer.
- **Change:** Runtime's existing resident key and AdapterPool remain the sole base/adapter owners. Catalogue entries are lazy descriptors; load only selected roles and reuse exact base/placement contexts. Bound candidate descriptors, active catalogue views and adapter cache count/bytes; use observed native buffers where available and disclose estimates separately. Evict only idle adapters; a cache-fit refusal becomes the declared resource fallback, not a host-wide admission gate. In-use handles stay pinned through their score attempt. Do not add a resident context per specialist or load every catalogue model during inspect/reload.
- **Change:** Operation groups already-ready requests by exact execution binding within its existing bounded live window; preserve output ordinals, source precedence and deadlines. Share immutable frame/render/token descriptors, but namespace KV/request/presentation reuse by base+adapter+execution identity. Preserve serial native decoding and its numerical receipts. Add prefetching/heterogeneous kernels only after measured load/transfer/batch fragmentation justifies a separately scoped backend change; an unbounded catalogue must not imply unbounded resident memory.
- **Test:** one base with several adapters loads base weights once; alternating hot/cold roles reports actual load/eviction/transfer/decode costs. A→B→base→A and cancelled/failed calls never reuse another adapter's state. Fixed live/cache limits bound memory as catalogue grows; busy adapters are not evicted and ordered results remain correct.

## 7. Atomic portfolio publication, retirement and graph limits

- **Defect:** updating specialists and router independently can route to absent/stale models; an ever-growing tree accumulates overlapping low-value specialists and extra routing calls.
- **Change:** publish one immutable complete application containing catalogue/router/policy references, then use existing expected-incumbent point/promote/rollback transaction. Extend the same Entry/reference decoder, not a second pointer kind/controller. Each Call pins one application snapshot; installation reuses compatible Runtime residents, retains old views for active calls and releases obsolete views afterward. Releasing a role view must not call BoundScorer.close, which closes its shared ResidentBase; Runtime releases an unreferenced base only after all epoch/call users drain. Lazy failures follow §2; retirement affects new Calls only. Never reload all weights or mutate an in-flight role.
- **Change:** cycle records add/update/consolidate/retire proposals using measured use, overlap, quality and residency cost. Consolidation trains one replacement on the union of referenced permitted populations; evaluate the replacement routed application before removing either old entry. Retire routing references through the same portfolio promotion and keep prior immutable artifacts for rollback; disk deletion remains files.prune's separate operation. Input-feature index/hierarchy is only a lookup optimization with identical eligible outputs. Existing compiler dependencies define actual multi-stage DAGs; no recursive model spawning or learned agent graph for independent judgments.
- **Test:** concurrent calls/reload/retirement observe one complete epoch; stale-incumbent promote and missing payloads cannot partially update serving. Router cannot select a removed ID. Consolidation preserves minority scopes and shared families; old calls finish, idle views release once, and rollback restores the entire prior routing policy without retraining.

Implementation references: [RouteNLP failure-guided distillation](https://arxiv.org/html/2604.23577v1#S3.SS3) informs the offline loop; [Grow-on-Demand](https://ojs.aaai.org/index.php/AAAI/article/view/40077) studies internal LoRA expert expansion, not this endpoint portfolio. [S-LoRA](https://arxiv.org/abs/2311.03285) informs shared-base residency; its CUDA paging/batching is not an existing capability here. Use the actual [risk-control formulation](https://arxiv.org/abs/2208.02814) for any claimed calibration guarantee, not a correctness-only score quantile.
